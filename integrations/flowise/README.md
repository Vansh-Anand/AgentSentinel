# Flowise custom tool bridge

This is a local custom-tool recipe for the AgentSentinel adapter. It is not evidence of a running Flowise canvas until installed and verified in Flowise. The adapter itself is covered by the repository API tests.

With the local demo running, `python scripts/flowise_adapter_smoke.py` checks the same HTTP adapter contract. It records a matching run/request ID for an allowed README read and a denied `.env` read, confirms the denied executor was not invoked, and verifies both local signed receipts. This smoke script does not invoke Flowise.

`node integrations/flowise/bridge-smoke.cjs` additionally executes the exact Custom Tool JavaScript body with Flowise-like variable bindings and a mocked `node-fetch` import against the running API. It checks an allowed public document response, a denied `.env` read, and idempotent replay of one invocation. This validates its request/response mapping, but it is still a simulator, not canvas-level proof.

Flowise's official [Custom Tool documentation](https://docs.flowiseai.com/integrations/langchain/tools/custom-tool) describes Input Schema properties exposed with a `$` prefix in its JavaScript Function. [Tools & MCP documentation](https://docs.flowiseai.com/tutorials/tools-and-mcp) describes `$vars`, `$flow` and the requirement to return a string.

1. Run AgentSentinel locally. Flowise must also run as a **local process on this host**, because this API accepts loopback clients only. A separate Docker container cannot reach the loopback-bound demo through `host.docker.internal`.
2. Create a local anonymous session with `POST http://127.0.0.1:8008/api/lab/session`, then use its `X-Lab-Session` header to `POST /api/lab/adapter/capabilities` with `{"role":"incident_analyst","lifetime_seconds":300}`. Store only the returned short-lived capability `token` as a private Flowise variable named `agentSentinelCapability`. Set `agentSentinelUrl` to `http://127.0.0.1:8008`. **Do not give the lab session token to Flowise** or put either token in an export, screenshot or source control. The capability binds the integration to a server-owned role, tool list, policy version, synthetic-run owner and expiry; it can be revoked by its nonce. Refresh it for a longer demonstration.
3. In Flowise, create a Custom Tool named `agentsentinel_action`. Describe it as the only way the agent may read synthetic files, search, calculate or create local artifacts. Use [tool-schema.json](tool-schema.json) for Input Schema and paste [custom-tool-function.js](custom-tool-function.js) into JavaScript Function. Ensure the Flowise instance supports `node-fetch` in custom tools as documented.
4. Attach only this custom tool to the Flowise Agent. Do not attach an independent shell, file, HTTP or ticket tool that could execute outside AgentSentinel. Use synthetic prompts and document data.
5. Test `read_file` with `{"path":"README.md"}`; then test `read_file` with `{"path":".env"}`. The tool result includes a run ID, request ID, decision, executor flag and signed-evidence status. Allowed public document and calculation calls return bounded tool output so the Flowise agent can continue a useful task. The `.env` result should be `PATH_OUT_OF_SCOPE` with executor invocation false and no output. A request for `review-brief.md` is denied to this external bridge before execution. Keep paired outputs and matching AgentSentinel run records as evidence.

The bridge returns decision metadata and bounded public synthetic tool output, not arbitrary filesystem contents. Approval-mode operations require action review in AgentSentinel and may outlast the bridge's bounded wait. The bridge never performs an independent action after a gateway check. Use a unique Flowise chat/session ID. The bridge derives a stable retry ID from the chat ID, tool and normalized arguments; submitting the same action again within that chat returns the original run instead of making another effect. This also intentionally treats a repeated identical tool call in one chat as the same request. The adapter run lookup accepts only the capability that created the run.

Earlier Flowise 3.1.4 install attempts in ignored `.data/` failed from partial npm dependency trees. On 19 October, repairing the local SQLite native module allowed a loopback Flowise server to complete startup at `http://127.0.0.1:3000`. Optional node loaders still report missing packages or an unsupported Couchbase native build on Node 24, so this is not a clean reproducible Flowise install. The browser reached Flowise's first-run administrator setup page. A human administrator must create that local account; no credential is stored in this repository. A genuine AgentSentinel custom-tool canvas run with paired allow/deny receipts remains unverified. Do not present the adapter simulator or a running login page as proof of Flowise execution.
